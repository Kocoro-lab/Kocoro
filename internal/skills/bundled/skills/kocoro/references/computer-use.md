# Computer-use runtime contract

This reference records the cross-process contract for Kocoro Desktop and daemon maintainers. The local routes below are an internal controller surface, **not model tools**: agents must not call them through raw `http`. The mutation/control plane requires `X-Kocoro-Local-Presence`; display topology is a read-only authority endpoint.

## Architecture boundary

- `computer_use` is Accessibility-first. Typed AX observations and semantic actions are the primary path; exact-window screenshots and CoreGraphics pointer input are a conservative fallback.
- AX, the Swift helper, and synthetic input remain internal services. Daemon computer-use runs no longer expose the legacy model-visible `accessibility`, `computer`, or `applescript` function tools; removing those public choices does not remove the internal services used by `computer_use` and provider adapters.
- A coordinate is actionable only while bound to the latest immutable `CoordinateFrame` and matching AX state, window identity, helper boot, display-topology identity/generation, and expiry. Kocoro frame metadata stays inside the adapter/runtime. Provider-native schema transport is still a cutover gate: the current Cloud hop does not preserve and attest the required native tagged union/provider/model/profile contract. The rollback-compatible `computer` executor therefore remains an ordinary function tool; only the disabled AX-first adapter owns the Anthropic-native identity.
- Generic `CaptureAndEncode` remains shared by browser, Ghostty, AppleScript, and standalone screenshot paths. Coordinate capture has an isolated resize/encode pipeline so its final bytes and tool dimensions cannot diverge.
- `type` normally requires the latest `state_id` plus its focused element `ref`; `hotkey` is intentionally window-bound and rejects a `ref`. The daemon sends the observed AX path, role, and fingerprint for element-bound `type`. The helper resolves that exact bounded path inside the identity-verified focused window and requires it to equal the live `AXFocusedUIElement` before touching the clipboard and again immediately before posting keyboard input. Editors that expose no focused AX element have one narrow fallback: a verified, non-consequential single left coordinate click mints a one-shot type handoff for that exact app and window. The next ref-less `type` consumes it; another app/window observation or any other action invalidates it. The helper never restores lost focus for this fallback and returns only `completed_unverified` because AX read-back is unavailable. The observed AX window bounds are correlation evidence, not mislabeled exact Quartz authority: the helper admits them only when they match the exact CGWindow bounds within 2 logical points on every axis and dimension. Typed text and key content never appear in results or `computer_use.activity`. `scroll` likewise requires the latest `state_id`, exact `ref`/path/role/fingerprint, bundle, PID, and unique window. Exactly one signed `dx`/`dy` is accepted as 1–10 semantic AX steps: positive means AXIncrement (right/down), negative means AXDecrement (left/up). It operates only through the target's matching AX scrollbar and verifies every step from a bounded AXValue change in the requested direction; it never emits a global scroll event or silently falls back to coordinates. Ref-less/stale/incomplete scroll remains fail-closed.
- Production `type` sends every string, including short ASCII such as `Zoro`, through the target-bound clipboard transaction. This avoids interpreting Latin search text through the user's active CJK input method. Direct `osascript`/`cliclick` invocations through `bash` are rejected on daemon computer-use runs, so a failed semantic or visual path cannot bypass target binding and IME-safe insertion with shell-generated input events.

## Capability gates

- `computer_use_topology_v1`: `GET /local/computer-use/topology` returns the strict logical-point display topology.
- `computer_use_control_v1`: the daemon supports the activity snapshot, heartbeat, and control routes below. Desktop may use conservative legacy UI only when this token is absent. If the token is present, transport, decode, or endpoint errors are degraded/fail-closed states, never a legacy fallback signal.
- `computer_use_app_policy_v1`: the daemon retains a local-presence-protected Ask/Blocked per-app policy for built-in safety and wire compatibility. Desktop does not expose a per-app editor; Always Allow is the separate global `permissions.always_allow_tools` grant for `computer_use`.
- `computer_use_physical_interference_v1`: synthetic coordinate pointer move/click, coordinate drag, target-bound keyboard/type, strict `semantic_text_selection_v2`, strict `semantic_press_v2`, and strict `semantic_scroll_v1` yield with a typed `user_interference` outcome when cursor drift or competing HID hardware-event counters/held mouse buttons/held modifier flags are observed during their bounded commit and verification windows. This uses `CGEventSource` HID state only: it installs no global event tap, requests no Input Monitoring permission, reads no event payload, and does **not** claim complete visibility into every ordinary keyboard event (including a non-modifier key already held before the first sample). If the required observation is unavailable, mutation fails closed or reports a committed-but-unverified outcome according to whether an input side effect already occurred. The Go resolver seals the latest `state_id` ref to its path, role, and fingerprint; the helper treats the ref label as opaque audit authority and independently revalidates the live PID, bundle id, unique window id, bounded path, role, fingerprint uniqueness, sensitivity, enabled state, explicit fallback policy, and deadline. It applies a scoped AX messaging timeout to the exact action and verification element and returns `commit_state=not_committed|committed|unknown`. `kAXErrorCannotComplete`, generic AX failure, transport loss, and malformed acknowledgements are never treated as safe failures or retried automatically. Scroll scans fingerprint uniqueness once under a total timeout, then each step/poll re-resolves only the exact window/path and bounded target/scrollbar metadata; results include `steps_completed`/`expected_steps`, so a boundary, no-op, wrong direction, timeout, or partial completion cannot masquerade as full success. Stop/Take Over uses an authority-derived request marker; Go keeps the action barrier until Swift returns a typed cancelled acknowledgement. Selection is verified only when the exact requested UTF-16 range is read back; an unsupported target may return `fallback_required`, but coordinate drag remains a separate model decision and is never implicit. Because press v2 declares no causal postcondition, a successful AXPress remains `completed_unverified`; target change alone is never called verified. Direct `set_value`, focus, and launch are not advertised and fail before target resolution, lease authority, or AX RPC until dedicated strict implementations exist. This execution contract does not by itself claim consequential-action confirmation parity.
- `computer_use_risk_confirmation_v1`: a local Desktop decision can grant either an exact typed-AX `computer_use.press` or one framed synthetic-coordinate **single left click** whose pixel hits one exact typed AX button. Classification uses bounded Title/Description/Desc/Identifier and exact current AX window metadata, never the model description. Semantic press currently admits exact send-like intent. Coordinate click admits send, delete, or purchase only when trusted AX metadata also supplies the required exact destination/object/amount detail; ambiguous or insufficient detail fails closed. Its target digest additionally binds AX path, immutable frame id/expiry/final-image digest, topology/helper/display authority, source pixel, and mapped Quartz point. During the wait, activity exposes only `{schema_version,required,kind,intent_id,expires_at}`. The grant binds the complete canonical detail as well as target digest, is one-shot, never outlives the 30-second frame, and is invalidated by denial, cancellation, Stop, Take Over, re-observation drift, expiry, or turn end. Immediately before helper commit, Go re-observes the complete AX tree/state. Swift then uses per-reference bounded AX calls to re-resolve the exact window title, path, role, fingerprint, enabled/AXPress metadata, target frame, and z-order hit after the physical-input baseline; drift, timeout, or competing physical input prevents the click. A generic tool approval cannot satisfy this separate decision, and right/double click, drag, or keyboard action cannot borrow the grant.

## Desktop-only routes

- `GET /local/computer-use/activity` — authoritative revisioned snapshot; requires local presence.
- `POST /local/computer-use/heartbeat` — renews the active lease owned by the connected Desktop controller.
- `POST /local/computer-use/control` — idempotent `pause`, `resume`, `take_over`, or `stop` transition.
- `GET /local/computer-use/topology` — current helper/display topology used to project the logical pointer; read-only and not action authority by itself.
- `GET /local/computer-use/app-policy` — redacted policy snapshot containing only canonical bundle ids, Ask/Blocked decisions, and built-in/user sources.
- `PUT /local/computer-use/app-policy` — sets one explicit Ask or Blocked user rule.
- `DELETE /local/computer-use/app-policy` — revokes one user rule back to default Ask; built-in rules are immutable.
- `GET /local/computer-use/risk-intents/{intent_id}` — no-store exact confirmation detail for authenticated local Desktop only.
- `POST /local/computer-use/risk-intents/{intent_id}/decision` — one-shot local allow/deny; the body must echo the path intent id.

The daemon owns one global lease. A mutating GUI tool waits for a real Desktop heartbeat before committing input. Each successful observation that resolves an exact, non-blocked bundle admits that app for later mutation in the same workflow, which supports natural multi-app tasks without asking for a new turn. A mutation can never create or widen this set, so an unobserved or blocked app still fails closed. Pause/Take Over/Stop cancel the active action and preserve an action-quiescence barrier until the executor acknowledges cleanup; no second workflow may enter while the first action can still commit input. Lease expiry follows the same barrier. The `take_over` HTTP response itself waits for that acknowledgement and returns `quiesced=true`; Desktop rechecks its connection generation, coordinator, lease, and revision before activating the target app. A spontaneous `user_interference` result also pauses the lease in `waiting_for_user`. Resume retains a mutation barrier until a new `computer_use.get_app_state` observation completes with a verified result; a successful wait or standalone screenshot does not clear stale UI authority.

The product exposes one Computer Use permission across apps and agents: Deny, Allow Once, or global Always Allow. An explicit persisted global `computer_use` grant is honored by both interactive and unattended runs; without it, unattended execution fails closed rather than inferring consent from `daemon.auto_approve` or the absence of approval UI. Built-in self/security/shell blocks remain immutable, and separate consequential-action confirmation, lease/Stop/Take Over, and physical-interference gates remain authoritative. The older Ask/Blocked per-app store stays internal for compatibility and built-in policy; Desktop no longer exposes per-app overrides. Legacy GUI tool names cannot use the global grant.

The consequential slice is intentionally narrower than generic mutation approval. Right/double coordinate click, coordinate drag, Return/Enter/Space, hotkey/type, legacy `computer`/`accessibility`, and any path that cannot derive exact intent from trusted typed AX metadata cannot receive this grant and must not be treated as a point-of-risk equivalent. A single left coordinate click is covered only when its immutable frame point maps to one unambiguous typed AX button and the helper can re-resolve the same button and z-order hit at commit. Detecting hidden consequential meaning for every unclassified coordinate/key/legacy action is not yet a global guarantee. Therefore this slice is **not release qualification** for every consequential action or for deleting the legacy implementations from source; the model-visible cutover is enforced separately by the run-local registry. Slack/Electron is admitted only when its partial AX tree still supplies the exact role/path/frame/fingerprint and non-generic window title (plus object/amount detail where required); otherwise it fails closed rather than trusting pixels or model prose alone.

`computer_use.activity` events carry only structured, redacted state. Desktop orders them by `(coordinator_instance_id, revision)`, repairs gaps from the snapshot endpoint, and invalidates pointer projection on topology changes.

## Legacy migration

The V1 daemon cutover exposes exactly one computer-use contract per run. A trusted Cloud profile selects its provider-native adapter or the generic function tool. Old or unavailable Cloud profile resolution selects the AX-only generic `computer_use`; it does **not** re-expose `computer`, `accessibility`, or `applescript`. If the selected contract cannot safely reach a target, the run fails explicitly rather than switching to a fixed-canvas, unbound AX mutation, AppleScript, or shell input path. Browser tools remain available for real web pages, but their page coordinates are not native-app coordinates.

Legacy wrapper implementations remain in source only for controlled rollback, adapter construction, and focused compatibility tests. They are not model-visible on daemon computer-use runs. Preserve the AX helper and semantic/action implementations behind `computer_use`; removing the wrappers never means removing Accessibility itself.
